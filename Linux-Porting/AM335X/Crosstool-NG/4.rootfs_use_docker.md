# BeagleBone Black Alpine Rootfs

本章建立 BeagleBone Black（AM335x）的 ARMv7 Alpine rootfs，放入 SD 卡第二分區。U-Boot、`MLO`、kernel 與 DTB 的建置與複製請依 [2.u-boot.md](2.u-boot.md) 和 [3.kernel.md](3.kernel.md)；本章不重複這些步驟。

> 本文使用主線 kernel 的 UART 名稱 `ttyS0`。若使用舊 TI kernel，所有 `ttyS0` 必須一致改為 `ttyO0`。

## 1. 匯出 Alpine rootfs

主機須有 Docker。x86_64 主機先註冊 ARM binfmt：

```bash
sudo docker run --privileged --rm tonistiigi/binfmt --install arm
mkdir -p "$HOME/bbb-rootfs" && cd "$HOME/bbb-rootfs"
export ALPINE_TAG="3.22"
export CONTAINER_ID="$(sudo docker create --platform linux/arm/v7 alpine:$ALPINE_TAG)"
sudo docker export "$CONTAINER_ID" -o alpine-rootfs.tar
sudo docker rm "$CONTAINER_ID"
mkdir rootfs
sudo tar -xpf alpine-rootfs.tar -C rootfs
export ROOTFS_DIR="$PWD/rootfs"
```

- `tonistiigi/binfmt`：讓 x86_64 Docker 可處理 ARMv7 映像；ARM 主機可略過。
- `mkdir ... && cd ...`：建立並進入工作目錄。
- `ALPINE_TAG`：固定 Alpine 版本，讓流程可重現。
- `docker create --platform linux/arm/v7`：建立 ARMv7 容器但不執行它。
- `docker export`：將容器檔案系統輸出成 tar；`docker rm`：刪除暫存容器。
- `tar -xpf`：保留檔案權限與擁有者解開 rootfs。
- `ROOTFS_DIR`：保存工作 rootfs 路徑，供後續指令使用。

## 2. 設定 rootfs

以下設定會在開機時自動套用 hostname、掛載虛擬檔案系統、啟用 `lo`，並讓 `eth0` 以 DHCP 取得網路。

```bash
printf '%s\n' 'beaglebone' | sudo tee "$ROOTFS_DIR/etc/hostname" > /dev/null
sudo install -d -m 755 "$ROOTFS_DIR/proc" "$ROOTFS_DIR/sys" "$ROOTFS_DIR/run" "$ROOTFS_DIR/dev/pts" "$ROOTFS_DIR/etc/init.d"
sudo tee "$ROOTFS_DIR/etc/fstab" > /dev/null <<'EOF'
proc  /proc     proc   defaults            0 0
sysfs /sys      sysfs  defaults            0 0
devpts /dev/pts devpts gid=5,mode=620      0 0
tmpfs /run      tmpfs  defaults            0 0
EOF
```

- 第一個命令寫入主機名稱。
- `install -d`：建立掛載點；`mount` 不會自行建立 `/dev/pts`。
- `fstab`：定義 `/proc`、`/sys`、`/dev/pts` 與 `/run` 的開機掛載。

```bash
sudo tee "$ROOTFS_DIR/etc/init.d/firstboot-network" > /dev/null <<'EOF'
#!/bin/sh
ip link set lo up
ip link set eth0 up
exec udhcpc -i eth0
EOF
sudo chmod 755 "$ROOTFS_DIR/etc/init.d/firstboot-network"
sudo sed -i '\|^::sysinit:/bin/hostname -F /etc/hostname$|d;\|^::wait:/etc/init.d/firstboot-network$|d;\|^ttyS0::respawn:|d' "$ROOTFS_DIR/etc/inittab"
sudo sed -i '1i ::sysinit:/bin/hostname -F /etc/hostname' "$ROOTFS_DIR/etc/inittab"
sudo sed -i '/^::wait:\/sbin\/openrc default/i ::wait:/etc/init.d/firstboot-network' "$ROOTFS_DIR/etc/inittab"
printf '%s\n' 'ttyS0::respawn:-/bin/sh' | sudo tee -a "$ROOTFS_DIR/etc/inittab" > /dev/null
```

- `firstboot-network`：先啟用 loopback `lo`，再啟用 `eth0` 並以 BusyBox `udhcpc` 取得 DHCP 租約與預設路由。
- `chmod 755`：讓 BusyBox init 可以執行此腳本。
- `sed -i`：先刪除同名設定，再加入 hostname、網路與首次 root shell 的 inittab 條目，因此可重複執行而不重複設定。
- `::sysinit`：在登入前設定 hostname；`::wait`：等待 DHCP 完成；`ttyS0 ... -/bin/sh`：首次開機直接進入 root shell，設定密碼後必須移除。

## 3. 安裝到 SD 卡與設定 U-Boot

先用 `lsblk -f` 確認 SD 卡掛載點。以下假設 ext4 rootfs 分區掛載於 `/media/$USER/rootfs`；依實際結果調整。

```bash
lsblk -f
export SD_ROOTFS_DIR="/media/${USER}/rootfs"
test -d "$SD_ROOTFS_DIR"
sudo rsync -aHAX --numeric-ids "$ROOTFS_DIR/" "$SD_ROOTFS_DIR/"
sync
```

- `lsblk -f`：確認掛載點，避免複製到錯誤磁碟。
- `test -d`：確認目標目錄存在。
- `rsync -aHAX --numeric-ids`：保留 rootfs 的權限、連結、ACL、extended attributes 與 UID/GID。
- `sync`：將快取資料寫入 SD 卡。

若尚未建立 `uEnv.txt`，在 FAT boot 分區建立它。假設該分區掛載於 `/media/$USER/boot`：

```bash
export BOOT_DIR="/media/${USER}/boot"
sudo tee "$BOOT_DIR/uEnv.txt" > /dev/null <<'EOF'
bootfile=zImage
fdtfile=am335x-boneblack.dtb
console=ttyS0,115200n8
mmcroot=/dev/mmcblk0p2 rw
mmcrootfstype=ext4 rootwait
loadimage=fatload mmc 0:1 ${loadaddr} ${bootfile}
loadfdt=fatload mmc 0:1 ${fdtaddr} ${fdtfile}
mmcargs=setenv bootargs console=${console} root=${mmcroot} rootfstype=${mmcrootfstype}
uenvcmd=run loadimage; run loadfdt; run mmcargs; bootz ${loadaddr} - ${fdtaddr}
EOF
sync
sudo umount "$BOOT_DIR" "$SD_ROOTFS_DIR"
```

- `uEnv.txt`：指定 kernel、DTB、UART console 與 SD 卡第二分區 rootfs。
- `bootz`：啟動 `zImage`；中間的 `-` 表示不使用 initramfs。
- `umount`：安全卸載 SD 卡分區。

## 4. 第一次開機

接上 3.3V USB-to-TTL（115200 8N1），由 SD 卡開機。進入 root shell 後執行：

```bash
mount -a
passwd root
ip addr show eth0
ip route
ping -c 3 8.8.8.8
```

- `mount -a`：掛載 fstab 定義的虛擬檔案系統。
- `passwd root`：設定非空 root 密碼。
- 後三行：確認 DHCP 已提供 IP、預設路由與外網連線。

時間錯誤會使 HTTPS 憑證驗證失敗，因此先校時，再更新索引與安裝工具：

```bash
ntpd -n -q -p pool.ntp.org
apk update
apk add openrc openssh iproute2
rc-update add sshd default
```

- `ntpd -n -q`：校時後離開，讓 `apk` 能驗證 HTTPS 憑證。
- `apk update`：下載套件索引。
- `apk add`：安裝 OpenRC、SSH 與完整 `ip` 工具。
- `rc-update add sshd default`：讓 SSH server 在日後開機時啟動。

## 5. 恢復安全的序列登入

確認密碼已設定後，將首次 root shell 改為正常登入並重開：

```bash
sed -i 's|^ttyS0::respawn:-/bin/sh$|ttyS0::respawn:/sbin/getty -L ttyS0 115200 vt100|' /etc/inittab
reboot
```

- `sed -i`：以會驗證密碼的 getty 取代直接 root shell。
- `reboot`：重新啟動；之後應看到 `beaglebone login:`。

## 常見問題

| 現象 | 處理方式 |
| --- | --- |
| `Unable to mount root fs` | 確認 `root=/dev/mmcblk0p2`，且 MMC/ext4 驅動編譯為 built-in。 |
| `apk update` 的 TLS 錯誤 | 確認 `ip route` 有 default route，並先以 `ntpd -n -q -p pool.ntp.org` 校時。 |
| 沒有網路 | 檢查 `ip addr show eth0`、`ip route` 與網線；`firstboot-network` 會在登入前執行 DHCP。 |
| hostname 顯示 `(none)` | 確認 `/etc/inittab` 第一行為 `::sysinit:/bin/hostname -F /etc/hostname`。 |
