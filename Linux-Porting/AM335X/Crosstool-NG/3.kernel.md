# AM335x Kernel 編譯與 U-Boot 開機

本章在主機端交叉編譯 Linux kernel，將映像與裝置樹放入 SD 卡的 `boot` 分區，最後從 U-Boot 載入。目標板為 **BeagleBone Black（AM335x）**，並沿用前章以 Crosstool-NG 建立的工具鏈。

> 本章假設 SD 卡第一分區為 FAT 格式的 boot 分區，第二分區為 ext4 格式的 rootfs 分區；其建立方式見 [2.u-boot.md](2.u-boot.md)。

## 1. 先備條件

主機需要 Git、編譯工具與 Device Tree Compiler：

```bash
sudo apt update
sudo apt install git build-essential bc bison flex libssl-dev libelf-dev libncurses-dev device-tree-compiler
```

- `apt update`：更新 APT 套件索引。
- `apt install`：安裝抓取原始碼、編譯 kernel 與產生裝置樹所需的工具與函式庫。
- `bc`：kernel 建置時用於計算版本資訊。
- `bison`、`flex`：產生 Kconfig 與部分 kernel 工具的剖析器。
- `libssl-dev`、`libelf-dev`、`libncurses-dev`：提供 kernel 功能與設定介面需要的標頭檔。
- `device-tree-compiler`：編譯與檢查 Device Tree Blob（DTB）。

## 2. 取得固定版本的 Linux 原始碼

本教學使用 `v7.2` tag；日後若更換版本，應同步記錄與測試。

```bash
git clone --depth 1 --branch v7.2 https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git
cd linux
git describe --tags --always
```

- `git clone --depth 1 --branch v7.2 ...`：只下載 `v7.2` tag 的最新提交，減少下載量並固定可重現的原始碼版本。
- `cd linux`：進入 Linux 原始碼目錄。
- `git describe --tags --always`：顯示目前提交對應的版本，確認沒有在錯誤的 branch 或 tag 上建置。

> 若需要 Torvalds 的主線原始碼，將網址改為 `https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git`；主線版適合開發，但 stable 版較適合作為首次 bring-up 的基準。

## 3. 設定交叉編譯環境

在每一個新的 shell 都執行下列指令，或將它們放入專案專用的環境設定檔：

```bash
export PATH="${HOME}/x-tools/arm-cortex_a8-linux-gnueabihf/bin:${PATH}"
export ARCH=arm
export CROSS_COMPILE=arm-cortex_a8-linux-gnueabihf-
arm-cortex_a8-linux-gnueabihf-gcc --version
```

- `export PATH=...`：把 Crosstool-NG 工具鏈目錄加入搜尋路徑，使 Makefile 找得到交叉編譯器。
- `export ARCH=arm`：要求 kernel 以 32-bit ARM 架構建置。
- `export CROSS_COMPILE=...-`：指定工具名稱的前綴；kernel 會據此呼叫 `...-gcc`、`...-ld` 等程式。
- `...-gcc --version`：驗證工具鏈可被 shell 找到。若此指令失敗，後續建置也一定會失敗。

## 4. 設定 kernel

先清除舊的設定與建置結果，再載入 ARMv7 多平台預設設定：

```bash
make mrproper
make multi_v7_defconfig
make menuconfig
```

- `make mrproper`：刪除舊的 `.config`、產物與暫存檔。它也會刪除手動放入原始碼樹的檔案，請勿在有未備份變更時執行。
- `make multi_v7_defconfig`：載入支援 AM335x 在內的 ARMv7 多平台預設設定。
- `make menuconfig`：開啟文字式設定介面，供檢查或調整功能；若不需調整設定可略過。

首次開機至少確認下列選項啟用，否則可能無法掛載 SD 卡或 rootfs(不過目前在 7.2 底下這些選項都有正常)：

```text
Device Drivers  ---> MMC/SD/SDIO card support  ---> MMC block device driver
Device Drivers  ---> MMC/SD/SDIO card support  ---> TI specific MMC/SDIO drivers
File systems    ---> The Extended 4 (ext4) filesystem
```

若要由 kernel 直接掛載 rootfs，將這些功能編譯為 `[*]`（built-in），而非 `[M]` 模組；因為 rootfs 尚未掛載時無法載入模組。

儲存後可保留目前設定：

```bash
cp .config am335x_defconfig
```

- `cp .config am335x_defconfig`：複製實際使用的設定，讓日後可追蹤與重新使用。這不是 kernel 的正式 defconfig 目錄，僅是本專案的設定備份。

## 5. 編譯 kernel、模組與裝置樹

```bash
make -j"$(nproc)" zImage
make -j"$(nproc)" modules
make -j"$(nproc)" dtbs
```

- `make -j"$(nproc)" zImage`：以所有可用 CPU 核心編譯可壓縮的 ARM kernel 映像；輸出為 `arch/arm/boot/zImage`。
- `make -j"$(nproc)" modules`：編譯設定為模組的驅動程式；第一次只測試 kernel panic 時可暫時略過，但要完成系統仍需要它。
- `make -j"$(nproc)" dtbs`：編譯 Device Tree Blob；BeagleBone Black 使用 `am335x-boneblack.dtb`。

用下列命令確認必要檔案已產生：

```bash
ls -lh arch/arm/boot/zImage arch/arm/boot/dts/ti/am335x-boneblack.dtb
```

- `ls -lh ...`：列出檔案大小與路徑。若任一檔案不存在，應先處理建置錯誤，不要進行 SD 卡複製。

## 6. 安裝到 SD 卡

先插入 SD 卡，找出 boot 與 rootfs 的掛載位置：

```bash
lsblk -f
```

- `lsblk -f`：顯示分區、檔案系統、卷標與掛載點，用來確認哪一個分區是 FAT boot、哪一個是 ext4 rootfs。

以下範例假設 boot 分區掛載於 `/media/$USER/boot`，rootfs 分區掛載於 `/media/$USER/rootfs`。請先依 `lsblk -f` 的結果調整，避免複製到系統磁碟：

```bash
export BOOT_DIR="/media/${USER}/boot"
export ROOTFS_DIR="/media/${USER}/rootfs"
test -d "$BOOT_DIR" && test -d "$ROOTFS_DIR" # echo $? 顯示出來的是 0 才是正確的
```

- `export BOOT_DIR=...`、`export ROOTFS_DIR=...`：集中定義兩個掛載目錄，避免後續指令重複輸入路徑。
- `test -d ...`：確認兩個目錄存在；指令沒有輸出且結束碼為 0 才表示可繼續。

複製開機檔案與安裝模組：

```bash
cp arch/arm/boot/zImage "$BOOT_DIR/zImage"
cp arch/arm/boot/dts/ti/omap/am335x-boneblack.dtb "$BOOT_DIR/am335x-boneblack.dtb"

# module install
sudo make INSTALL_MOD_PATH="$ROOTFS_DIR" modules_install
sync
```

- 第一個 `cp`：把 kernel 映像複製到 FAT boot 分區，並使用後續 U-Boot 指令預期的檔名。
- 第二個 `cp`：複製 **AM335x BeagleBone Black** 專用 DTB。`am225x-boneblack.dtb` 是錯誤檔名，AM225x 與 AM335x 是不同平台。
- `sudo make INSTALL_MOD_PATH=... modules_install`：將模組安裝到 SD 卡 rootfs 的 `/lib/modules/<kernel-version>`。`sudo` 通常是因為 rootfs 內檔案屬於 root。
- `sync`：要求系統將尚未寫入裝置的快取資料完成寫入，再拔卡或供板子讀取。

## 7. 在 U-Boot 手動開機

先將 SD 卡插入 BeagleBone Black，連接序列主控台（115200 8N1），並在倒數時按任意鍵進入 U-Boot。以下指令假設 boot 分區是 SD 卡的第一分區：

```text
fatload mmc 0:1 0x82000000 zImage
fatload mmc 0:1 0x88000000 am335x-boneblack.dtb
setenv bootargs console=ttyO0,115200 root=/dev/mmcblk0p2 rootwait rw
bootz 0x82000000 - 0x88000000
```

- `fatload mmc 0:1 0x82000000 zImage`：從第一個 MMC 裝置的第一分區讀取 kernel，到 RAM 位址 `0x82000000`。
- `fatload mmc 0:1 0x88000000 am335x-boneblack.dtb`：讀取 DTB 到另一段不與 kernel 重疊的 RAM 位址。
- `setenv bootargs ...`：設定傳給 kernel 的參數。
  - `console=ttyO0,115200`：將主控台輸出導向 AM335x UART0；字母是大寫 `O`，不是數字 `0`。
  - `root=/dev/mmcblk0p2`：指定 SD 卡第二分區為根檔案系統。
  - `rootwait`：等待 MMC 裝置完成初始化，避免過早掛載 rootfs 失敗。
  - `rw`：以可寫入模式掛載 rootfs。
- `bootz 0x82000000 - 0x88000000`：啟動 zImage；中間的 `-` 表示沒有 initramfs，最後一個位址是 DTB。

若 rootfs 尚未建立，kernel 在啟動後出現 `VFS: Unable to mount root fs` 或 kernel panic 是預期結果。這表示 kernel、DTB 與序列主控台已經開始運作；完成 [4.rootfs.md](4.rootfs.md) 後再以相同 `bootargs` 啟動即可。

## 8. 常見問題

| 現象 | 檢查方向 |
| --- | --- |
| `arm-cortex_a8-linux-gnueabihf-gcc: command not found` | 重新設定 `PATH`，並確認 Crosstool-NG 工具鏈實際安裝於 `${HOME}/x-tools`。 |
| U-Boot 找不到 DTB | 確認檔名為 `am335x-boneblack.dtb`，且已放到 FAT boot 分區。 |
| `Wrong Image Format for bootm command` | 此章產生的是 `zImage`，應使用 `bootz`，不是 `bootm`。 |
| `Unable to mount root fs` | 確認 rootfs 在第二分區、`root=/dev/mmcblk0p2` 正確，且 MMC/ext4 驅動編譯為 built-in。 |
| 沒有序列輸出 | 確認主控台是 `ttyO0`、鮑率為 115200，並檢查 UART 接線與 GND。 |
